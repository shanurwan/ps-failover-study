02 · Late commits

Where "duplicate rows" tickets come from

Every request had a 2 s deadline. When it passed, the app counted the write as failed. Many of those writes committed anyway.

Writes committed after the app gave up
Per switchover, through PgBouncer. Each one confirmed in the database.

Why pgx is near zero

pgx cancels the query when the context deadline passes, so the write usually never commits. node-postgres, Prisma, postgres-js, psycopg and ActiveRecord have no per-call cancellation: the write keeps going after the app has moved on.

What it means for a customer

  • The database lost nothing and duplicated nothing.
  • An app that retries a timed-out write without an idempotency key creates the duplicate itself.
  • Fix: a client-generated key with ON CONFLICT DO NOTHING, or an idempotency table.

On direct 5432, pgx also lost 12–13 acknowledgements in transit: the client saw an error, but the row was committed.

05 · Logical replication

When does a CDC slot survive a switchover?

One failover = true slot, three setups, one switchover each. Configured as documented with an active consumer, it came through with every change.

To check a replica holds a persistent copy: SELECT synced, temporary FROM pg_replication_slots on a replica. You want synced = t and temporary = f. Each case was run once.
06 · Method

How it was measured

Everything here is reproducible from the repository: clients, runner, raw request logs and the report generator.

1

Seven clients

pgx (two cancel modes), node-postgres, Prisma, Drizzle on postgres-js, SQLAlchemy + psycopg, Rails ActiveRecord.

2

Steady load

28 req/s per client, half inserts with a unique sequence number, every request logged with its verbatim error.

3

Real switchovers

pscale branch switchover, timed against PlanetScale's own started and completed records.

4

Audit the ledger

Every acknowledged write checked in the database afterwards: missing, duplicated, or committed late.

Limits. One cluster size (PS-5), one region. The direct-connection round used pgx only. Short ~2 s pauses that hit several clients outside any switchover were seen once and are not explained.
